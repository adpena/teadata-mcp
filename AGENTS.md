# Repository Guidelines

## Project Structure & Module Organization
- `src/teadata_mcp/`: Python MCP server code (routing, business logic, SSE entry point).
- `frontend/`: Vite + React + TypeScript UI; builds into `static_dist/` for the backend to serve.
- `tests/`: Pytest suite (`test_*.py`).
- `run_dev.sh`, `run_mcp.sh`: local/dev helper scripts; `Dockerfile` for deployment.

## Build, Test, and Development Commands
- `./run_dev.sh`: build frontend, sync Python deps via `uv`, run `uvicorn` (default port `8000`, auto-selects next free port; override with `--port`).
- Backend only: `uv sync`, then `uv run uvicorn teadata_mcp.sse_server:app --reload --port 8000`.
- Frontend dev server: `cd frontend && npm install --legacy-peer-deps && npm run dev`.
- Frontend build: `cd frontend && npm run build` (writes to `static_dist/`).
- Frontend lint: `cd frontend && npm run lint`.
- Cloudflare tunnel helper: `./run_mcp.sh` (use `-s` to skip frontend build; default port `8000`, auto-selects next free port; override with `--port`; requires `cloudflared`).
- Performance/log bundle: `./share_perf_report.sh` (writes `logs/share_perf_report_*.txt` and copies to clipboard).

## Coding Style & Naming Conventions
- Python: 4-space indent, type hints where practical, `snake_case` for modules/functions; keep server code under `src/teadata_mcp/`.
- Frontend: 2-space indent in TS/TSX; components in `PascalCase` (e.g., `CampusView.tsx`), utilities/types in `camelCase` or `types.ts`.
- Styling: Tailwind utility classes in `className`; keep new styles colocated with components.

## Testing Guidelines
- Framework: pytest in `tests/`; run with `uv run pytest`.
- Naming: `test_*.py` and `test_*` functions.
- Coverage: no explicit threshold; add tests for new tool routes or data engine behavior.

## Commit & Pull Request Guidelines
- Commit messages follow short, imperative summaries (e.g., "Add ...", "Document ...", "Fix ..."); keep scope in the body if needed.
- PRs should include: a clear description, linked issue if applicable, test command(s) run, and screenshots/GIFs for UI changes.

## Configuration & Deployment Notes
- `TEADATA_SNAPSHOT` can point to a prebuilt data snapshot; Docker uses `PORT` (default 10000).
- `static_dist/` is generated by the frontend build; avoid manual edits.
